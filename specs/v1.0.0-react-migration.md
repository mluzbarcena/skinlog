# Spec — Migration to React + Vite + TypeScript (v1.0.0)

- **Status:** Implemented ✅
- **Date:** 2026-09-16
- **Target version:** 1.0.0

## Context

`skinlog` is a personal skincare-routine tracking tool, originally written in vanilla
JavaScript (classic scripts under the `window.SK` namespace) with a homemade build
(`build.mjs`) that inlined everything into a single `dist/index.html`. The app worked and had a
clean architecture: the business logic was already isolated in pure functions
(`config.js`, `util.js`, `logic.js`, `storage.js`) and the UI lived separately (`ui.js`, `app.js`)
manipulating the DOM directly.

The goal was to move to **React + Vite + TypeScript** to improve maintainability, without
changing the behavior or the data model. Persistence stays in **localStorage** in this v1.0.0
(no backend, no external services, no API keys).

## Decisions

- **Language:** TypeScript.
- **Build:** standard Vite (multi-file, served over HTTP). `base: "./"` so `dist/` is portable
  (GitHub Pages, Netlify, subdirectories).
- **Styling:** Tailwind CSS v4 (`@tailwindcss/vite` plugin, CSS-first config) + the design
  system ported as CSS tokens and component classes in `src/index.css`.
- **PWA:** installable (manifest + icons + meta tags), with no extra dependencies.
- **Persistence:** same `skincareTracker:v1` key → existing data migrates on its own. Same state
  structure and same `migrate()` function.
- **i18n (es/en):** lightweight custom solution (dictionaries + `useI18n()` hook), no
  dependencies. Language in `settings.language` (persisted); default auto-detected from
  `navigator.language`. Globe icon button in the Topbar + selector in Settings.
- **Dark mode:** `.dark` class on `<html>` based on `settings.theme` (auto/light/dark);
  anti-flash script in `index.html`.

## Architecture

Domain ↔ view separation:

- **Domain (`src/domain/`)**: pure functions that receive the state explicitly (they don't read
  a singleton). The store (`storage.ts`) is a framework-agnostic external store
  (`subscribe` / `getSnapshot` + mutations) bound to React with **`useSyncExternalStore`**.
- **View (`src/components`, `src/views`)**: React components that read the state and call the
  store actions.
- **i18n (`src/i18n/`)**: `es.ts` is the source of truth and defines the `Dict` type; `en.ts`
  satisfies it. Typed interpolation via functions in the dictionary.

## Business rules (unchanged from the vanilla version)

- **Phases:** Phase 1 while `hyaluFinishedDate` is `null`; Phase 2 for dates
  `>= hyaluFinishedDate` (`logic.phaseForDate`).
- **Frequencies:** `retinolB3PerWeek` (0–7), `sanaPerWeek` (1–2, cap 2 after confirming
  tolerance). The app never raises them on its own: it only suggests (`logic.suggestNight`).
- **Retinol B3 and SANA** are distinct night types and never fall on the same night.
- **SANA Brightening** is an optional, filterable AM step (`settings.brightingEnabled`).
- **Hyalu B5** is marked finished from the Phases view → triggers Phase 2.
- Editable rules centralized in `src/domain/config.ts`; text in `src/i18n/`.

## Deliverables

1. Full source code (React + Vite + TS).
2. File structure (README + this spec).
3. Local: `npm install && npm run dev`.
4. Static build: `npm run build` → `dist/`; `npm run preview`.
5. Deployable ZIP: `skinlog-dist.zip`.
6. Persistence: single `skincareTracker:v1` key (settings + `days` by date).
7. Where to change rules: `config.ts` + `logic.phaseForDate` / `logic.suggestNight`.

## Verification

Automated (`npm run test`, Vitest — 13 tests):

- Initial phase, AM/PM completeness, Phase 1 → 2 transition.
- Retinol B3 and SANA as distinct nights; optional SANA Brightening doesn't break AM.
- Night suggestion, irritation warning, stats.
- Export/import roundtrip; empty day not persisted.
- Smoke test: the whole app renders without errors.

Manual in the browser (`npm run dev`, and on mobile with `npm run dev -- --host`):

- Data survives refresh; changing the date doesn't erase records.
- Marking Hyalu B5 activates Phase 2; SANA Brightening on/off; mobile usability.
- i18n: the globe button toggles es/en and persists; first visit auto-detects.

## Out of scope (v1.0.0)

- Backend, accounts, cross-device sync.
- Persistence other than localStorage.
